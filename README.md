# BookMarkSync

当前版本：**1.0.1**。本版补强目录切换、权限恢复、中断续传、文件校验，以及账号收藏栏暂时不可用时的处理。审查记录见 `REVIEW.md`，验证记录见 `VALIDATION.md`。

Chrome / Edge 的纯本地双向书签同步扩展。两端各安装一次，手动选择同一个本地文件夹，之后自动合并增删改。没有本地辅助程序、HTTP 服务或同步中介，安装使用不需要 Node、Python 或 npm。

**自带书签同步可以继续运行。** 本扩展不改变 Chrome / Edge 的账号或同步设置。厂商同步下载到本机的变化，会和本机编辑一样进入合并；本扩展自身不发网络请求。原生云同步仍按浏览器设置上传、下载书签。

## 安装

从 GitHub 仓库的 **Code → Download ZIP** 下载源码并解压，或用 Git 克隆仓库。项目可以放在任意固定的本地位置；实际需要加载的是项目中的 **`extension` 文件夹**，其中直接包含 `manifest.json`。请保留该文件夹，浏览器每次启动仍会从这里读取扩展代码。

1. 在 Chrome 打开 `chrome://extensions/`，开启开发者模式，点击“加载已解压的扩展程序”，选择上述 `extension` 文件夹。
2. 在 Edge 打开 `edge://extensions/`，同样加载这个文件夹。
3. 在两端打开 BookMarkSync 的设置页，分别点击“选择目录”，选择同一个普通本地文件夹。可以使用项目中的 `shared` 文件夹，也可以选择其他位置。同步目录与扩展代码目录是不同用途的文件夹。
4. 每端授予目录读写权限。浏览器弹窗出现“每次访问时都允许”时选择该项；首次选择目录时可能尚未出现，关闭再打开后按下方步骤恢复授权。
5. 确认预览，再分别点击“开始自动同步”。首次合并采用并集。

不需要开启“允许访问文件网址”，不需要下载权限，也不需要让设置页一直开着。扩展的公开 `key` 固定了身份，请在更新时保留 `manifest.json` 中的 `key`，不要卸载重装来升级。修改代码后在扩展管理页点击“重新加载”即可。

首次选择目录和原生权限确认需要你手动操作。关闭浏览器后，目录读写权限可能需要重新授予；扩展图标显示“授权”时，打开设置点击“恢复目录授权”。若清理数据或重装扩展使目录记录也被移除，则需重新选择原来的共享目录。

更换到其他目录会先暂停并显示预览，由你点击开始后应用；取消选择或新目录校验失败，会保留原连接。恢复目录授权不会替尚未启用或已暂停的用户自动开始同步。已经同步过的暂停端可以在预览后选择“立即同步”，仅同步一次。

安装时浏览器可能提示读取和更改书签、读取浏览记录。书签权限用于双向同步；标签页权限用于识别内置书签管理器的打开和切换，不采集或保存浏览历史，不读取网页内容。目录读写权限由你在两端分别授予，不能承诺永不失效。

## 关闭浏览器后如何恢复同步

**关闭再打开 Chrome 或 Edge 后，可能需要手动恢复目录授权，或恢复自动同步。** 若之前只授予本次访问权限，浏览器可能在会话结束后收回读写权限；即使扩展仍记得目录，也暂时不能交换文件。两端的授权相互独立，需要分别检查。

1. 在浏览器的扩展菜单中点击 BookMarkSync，打开设置页，查看顶部状态。
2. 若显示“需要目录授权”，或扩展图标显示“授权”，点击扩展内的 **“恢复目录授权”**。
3. 在随后出现的浏览器目录权限弹窗中，若有 **“每次访问时都允许”**（英文为 `Allow on every visit`），选择该项。它允许后续访问继续使用目录；“允许本次访问”（`Allow this time`）只适用于当前会话，下次启动可能还要恢复授权。Edge 或其他语言版本的措辞可能不同，以弹窗中表示持续允许该目录读写的选项为准。若仅提供本次允许，可先允许；之后仍可能需要再次手动授权。
4. 授权完成后，再按页面实际显示的状态和按钮操作：

| 设置页状态或按钮 | 应执行的操作 |
| --- | --- |
| “自动同步中” | 已恢复后台同步，无需再点恢复按钮；可点击“立即同步”检查本次交换是否成功 |
| “已暂停”或“等待开始”，并显示“恢复自动同步” | 检查预览后点击“恢复自动同步”，继续后台自动检查 |
| “等待开始”，并显示“开始自动同步” | 尚未成功完成过同步；确认首次合并预览后点击“开始自动同步” |
| “开始设置”或“尚未连接目录” | 点击“选择目录”，重新选择两端原来的共享目录，确认预览后点击“开始自动同步” |
| “等待重试”，或图标显示“!” | 阅读顶部具体错误，按错误处理；不要把所有错误都当作授权失效，也不要删除交换文件 |

恢复目录授权后，如果原先启用了自动同步，扩展会立即尝试同步；如果原先已暂停或尚未开始，则保持预览，等待你点击“恢复自动同步”或“开始自动同步”。**“立即同步”只执行一次，不会启用持续自动同步。** 恢复后确认顶部显示“自动同步中”、“最近同步”时间已更新；两端正常运行时，默认约 30 秒检查一次对端，浏览器调度或休眠可能延后。

“恢复目录授权”“恢复自动同步”“开始自动同步”是扩展中的实际按钮名称；“每次访问时都允许”属于浏览器原生弹窗，不是扩展按钮。“恢复记录”区域的“恢复”用于恢复书签内容。持久授权选项有时在关闭再打开后、点击“恢复目录授权”时才出现；选定后仍可能因主动撤销、清理数据、重装或浏览器策略而失效。扩展不能在后台替你确认权限弹窗，也不保证每次启动都无需操作。

浏览器原生权限选项及触发条件参见 [Chrome 官方持久授权说明](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api?hl=zh-cn)。扩展按钮及恢复行为以当前 `options.html`、`options.js` 和 `lib/engine.js` 为准。

## 日常行为

- 书签新增、标题或网址修改、移动、删除、排序会触发同步；连续操作约 1.2 秒后合并处理。
- 默认每 30 秒检查本地交换文件，可改为 1 / 2 / 5 分钟。
- 启动浏览器、切回浏览器窗口、打开或切回管理器标签页时补同步。
- 原生书签下拉菜单、Edge 内置收藏夹面板的展开没有统一公开通知，因此依靠后台同步保持更新。
- 浏览器调度或电脑休眠可能延后检查。关闭某一端不会删除它的数据；重新启动后，在自动同步已启用且目录授权可用时继续，否则按上方步骤恢复。
- 正常同步没有弹窗；目录授权失效或文件异常会显示图标提示。设置页提供暂停、立即同步、恢复记录和导出当前备份。
- 同步应用前自动备份本端原始书签树，每端保留最近 10 份，位于共享目录的 `backups` 下。

## 合并规则

首次按父文件夹、类型、标题、原始网址配对相同项；保留重复项的数量及匹配歧义。首次没有可靠的历史编辑时间，因此采用并集，不声称能还原安装前的编辑先后。

之后每条书签、文件夹有独立同步 ID，标题、网址、父位置、子项顺序、删除状态分别版本化。顺序列表中尚未出现的新项按固定顺序补入，因此并发新增不会丢失。

| 情况 | 结果 |
| --- | --- |
| 两端分别新增 | 都保留 |
| 一端改标题、另一端移动 | 两种修改都保留 |
| 同字段同时编辑 | 混合逻辑时钟决定相同的胜出版本，另一版进入两端恢复记录 |
| 一端删除、另一端编辑 | 删除优先，编辑后的内容仍保留在可恢复记录中 |
| 删除文件夹、另一端新增子项 | 新子项转入“其他收藏夹”，不会随文件夹一起误删 |
| 并发移动形成文件夹循环 | 按固定规则拆开循环，将一项放入“其他收藏夹” |
| 相同网址在不同文件夹 | 都保留，不按网址全局去重 |
| 企业只读收藏夹 | 不同步、不修改 |
| 同时存在本地和账号收藏栏 | 汇总到逻辑收藏栏；保留已有项所在的物理根目录，新建优先写入可云同步的根目录 |
| 多份物理收藏栏的顺序 | 各自内部顺序同步，物理收藏栏之间无法交错显示，不会因此反复应用或备份 |
| 账号根目录临时消失 | 保留相关书签及顺序；属于其子树的新增项等待根目录恢复，不推断为用户批量删除 |

删除以独立墓碑保存，避免落后的交换快照把已删除内容补回来。恢复操作会产生新的版本，传播到另一端。文件丢失、内容损坏、工作区标识变化时保留本地书签并等待重试，不把错误当作空目录。

工作区标识文件缺失时不会自动创建新工作区。请恢复原来的 `BookMarkSync.workspace.json`；若需从已有副本重建，可在备份后读取 `replica-*.json` 的 `workspace` 值，将标识文件恢复为 `{"schema":1,"type":"BookMarkSync","id":"这里填写原 workspace 值"}`，不要另造一个 ID。没有把握时先导出备份，保留整个共享目录。

原生云同步有时会替换本机书签 ID。内容完全匹配时会重新建立对应关系；带旧创建时间的已删除项会匹配原墓碑。若外部工具或云端将旧项以新的 ID、**新的创建时间**重新建立，浏览器 API 无法区分它与用户主动重新添加，此时视为新书签。

## 数据与权限

共享目录内容：

```text
BookMarkSync.workspace.json       工作区标识
replica-<本端唯一标识>.json        各端发布的版本化快照和恢复记录
backups/backup-<本端标识>-<时间>.json
```

每端只写自己的交换文件。使用 File System Access API 的写入流关闭后提交，不直接修改浏览器内部 `Bookmarks` 文件。目录句柄、原生 ID 对应关系、上次观察状态和应用中断标记存于当前扩展的 IndexedDB。

清单权限仅有 `bookmarks`、`alarms`、`tabs`。本地状态使用 IndexedDB，不申请未使用的 `storage` 权限。没有互联网主机权限、`nativeMessaging`、`downloads` 或 `file://` 权限；CSP 将 `connect-src` 设为 `none`。`tabs` 用于识别管理器标签页，不读取网页内容。

一份交换文件最多 20 MiB、最多 100,000 条含墓碑的记录；接收、合并及发布均检查限制，合并超限会在修改浏览器前停止。墓碑不按天数自动清理，以免长时间离线的端使删除项复活；因此超限后可能需要在导出备份、整理各端当前书签后，由所有参与端重新连接一个空目录建立新工作区。冲突保留最近 200 项，设置页分别显示最近 30 项删除和 30 项冲突。备份是 JSON 原始树，可用于故障调查和人工恢复。

## 开发与验证

扩展使用原生 JavaScript ES Modules，无编译流程和第三方运行时依赖。开发及单元测试使用 Node.js 24；以下命令在项目根目录执行：

```powershell
npm test
npm run check
npm run test:browser
npm run test:recovery
npm run test:folders
npm run test:permissions
npm run package
```

- `npm test` 使用真实生产合并、捕获、规划、应用和状态持久化逻辑；仅浏览器 API 和文件交换边界使用测试替身。
- `npm run check` 检查全部 JavaScript 语法、扩展清单、权限和 CSP。
- `npm run test:browser` 使用机器上实际 Chrome / Edge 的**独立临时配置**，通过开发者调试接口加载扩展。仅测试配置预置等价的持久目录授权，再取得真实目录句柄，实际跨浏览器交换磁盘文件；不自动点击原生权限弹窗，不修改日常用户配置。测试实例使用自动化模式并禁用其云同步、首次导入，避免接入真实账号或数据；这些启动参数不属于扩展，也不作用于日常浏览器。验证记录与截图写入 `work/browser-*`。
- `npm run package` 生成可加载扩展包和源码包，位于 `dist`。
- `npm run test:recovery` 在上一步通过的独立配置中真正停止扩展后台，检查无常驻设置页、无持续调试连接时能否由定时任务唤醒，同时检查实际备份文件。
- `npm run test:folders` 在独立配置中验证真实浏览器的嵌套文件夹、祖先关系交换、递归删除传播及 Chrome 管理器打开触发。
- `npm run test:permissions` 仅在独立测试配置中撤销、恢复目录授权，验证真实界面、徽标、暂停和手动同步行为；还验证新目录失败保留原连接、IndexedDB 事务回滚、工作区标识缺失及恢复。原生权限弹窗不自动操作。

测试不登录个人云账号。厂商云端服务的网络、账号和设备行为不由扩展控制；本地合并测试覆盖其通过书签 API 表现出的新增、修改、删除和 ID 替换。

Chrome 156 会在重启时移除通过 CDP 临时安装的测试扩展。测试脚本会重新挂载同一扩展，检查原有目录授权、IndexedDB 状态和后续同步是否保留，并在记录中注明；它不声称验证了原生安装或授权弹窗。正常使用请按前述步骤在扩展管理页手动加载一次。

代码结构：`model.js` 为版本合并及恢复；`capture.js` 将原生树变化转成操作；`bookmarks.js` 适配浏览器读写；`storage.js` 管理 IndexedDB 和目录文件；`engine.js` 串行执行同步；`background.js` 注册唤醒事件；`options.*` 提供设置和恢复界面。

## 仓库与本地数据

GitHub 仓库用于托管扩展源码、测试和文档，运行扩展不需要连接 GitHub。`shared` 中的书签交换文件与备份、`work` 中的临时浏览器配置及测试记录、`dist` 中生成的压缩包、`node_modules` 和本地密钥不会提交到仓库。清单中的 `key` 是固定开发版身份的公开公钥，不是私钥。

默认 Git 忽略规则可防止常见本地数据被误提交；不要使用 `git add -f` 强行上传书签、浏览器配置或密钥。修改代码后可运行 `npm run package`，在本地生成扩展包和源码包。
